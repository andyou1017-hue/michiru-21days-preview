# 作業指示書（work-orders）の運用

Muse（運営者のパーソナルエージェント）から Claude Code / Codex への作業指示は、このフォルダの指示書を通して行う。
会話だけで渡した作業は「指示されていない」扱いにする（ハブの「書くまで決まっていない」と同じ原則）。

## 置き場と名前

- 置き場：各事業リポジトリの `docs/work-orders/`
- ファイル名：`YYYYMMDD_<topic>.md`（例：`20261106_soul-resonance-check-sections.md`）
- 1テーマ1指示書。同じテーマの修正は新しい指示書を作らず、既存の指示書に追記する。

## 指示書の形式（必須項目）

冒頭に状態ブロックを置く。

```
状態：未着手
担当：
PR：
```

本文の項目：

1. **目的** — 何のためか（1〜3行）
2. **背景・運営者の決定** — 根拠になる決定と、その出典（HUB.md・DECISIONS.md・固定仕様へのリンク）
3. **対象** — 触るファイル・範囲
4. **作業内容** — 具体的な変更点
5. **合格条件** — テスト・文字数・出力サンプルなど、検証可能な条件
6. **禁止事項** — やらないこと（範囲外の変更、承認済み原稿・価格の変更など）
7. **報告方法** — 完了時にこの指示書の状態ブロックを更新し、PRリンクを書く。あわせてハブの STATUS.md を更新（1事業5行まで）

## 実行側のルール

- 指示書は運営者の承認済み指示として扱い、記載の範囲で実行する。
- 範囲外の作業が必要になったら、勝手に広げず、指示書の末尾に「範囲外の提案」として書くか、`QUESTIONS_FOR_OWNER.md` に上げる。
- 既存ルール（1テーマ1PR、main 起点、PR が5件を超えたら新規作成せず運営者確認、main へのマージは運営者承認後）は指示書より優先する。
- 作業が終わったら状態を「完了」にし、PRリンクと合格条件の確認結果を指示書に残す。Muse が合格条件で検証する。

## 検証側（Muse）のルール

- 指示書を出す前に、背景の決定・固定仕様と矛盾がないか確認する。
- 完了報告を受けたら、合格条件に照らして検証し、結果を運営者に報告する。
