# 2026-11-01｜受講生記録のサーバー保存：第1段階（未公開）

## 今回の実装（PR #2、正式原稿不変更）
- 招待・ログイン済みのアカウントだけが利用できる日別記録APIをゲートウェイへ追加。
- `POST /api/entry` は日番号1〜21、入力型・文字数を検証して、アカウントIDと日番号を複合キーとしてSQLiteへ保存する。
- `POST /api/entry/delete` と `POST /api/entries/delete-all` は**本人のアカウントに属する日別記録のみ**を削除。
- `GET /api/bootstrap` は本人の日別記録のみを返す。未招待者・未ログイン者は利用不可。
- `POST /api/delete-account` は従来のアカウント停止ではなく、認証情報・セッション・招待・日別記録をDBから削除するよう修正。
- テスト `tests/server-sync.test.js` で未認証拒否、利用者間の分離、入力検証、Origin拒否、削除を確認する構成を追加。

## まだ利用者の画面では有効化しない
**自動同期完成ではない。** 現在の `runtime/api.js` は `remote() => null`、配信HTMLは `localOnly:true`。端末内保存・プライバシー案内は従来どおり。ユーザー同意と同期ルールを設計する前に、黙って個人記録をサーバーへ送らない。

サーバー保存対象は日別の記録のみ。発見、書きかけ、未来からの手紙、7日間の開封制限は対象外。DBは運営側から技術的に参照可能な平文保存で、エンドツーエンド暗号化ではない。個人記録の収集に先立ち、保存場所・保存期間・アクセス権・削除・バックアップ保持期間・本人同意を決めること。

## 次の実装・受入試験
1. サーバー保存の任意の同意画面と、受講生に分かる説明文を用意。初回の同意前に記録を送らない。
2. 複数端末での更新競合、古い端末からの削除済み記録の復活、オフライン復帰、同期失敗の再試行をテストする。現在の `mergeRemote` は日時比較のみで、削除の墓標がない。
3. 「私の発見」「未来からの手紙」を含む全記録の同期範囲を設計。特に未来の手紙は本文を端末に先出ししないサーバー側の7日ロックを別途実装・検証。
4. 受講生向けHTTPS本番URL、Safari実機、バックアップ復元、招待コード配布を確認。
5. 教材・デザイン・33秒誘導の最終確認後にのみマージ・本番公開。
