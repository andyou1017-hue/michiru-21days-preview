# 招待制ゲートウェイ（未公開・最終承認前）

このリポジトリだけで動く、招待制の配信入口。Node.js 22.13以降／24、SQLiteを使用し、外部認証サービスには依存しない。
コードを追加しただけでは既存GitHub Pagesは保護されない。受講生用URLは、このサーバーをHTTPSで設置してから別途確認する必要がある。

## 現在の範囲

- 管理者がメールアドレス宛ての招待コードを発行。有効期限72時間、一回利用。
- 受講生は招待コード・メールアドレス・12〜128文字のパスワードで初回登録。以降はメール・パスワードでログイン。
- パスワードはsalt付きscrypt、招待コード・セッションは高エントロピー乱数をSHA-256で保存。
- セッション期限24時間。Cookieは本番でSecure/HttpOnly/SameSite=Strict/__Host-付き。Origin照合と試行回数制限あり。
- 未認証では教材・JS・生成JSON・bootstrapへの直URLを拒否。管理用コードやDBは配信しない。
- 利用者別に端末の保存キーを分離。ログアウト後も同じアカウントで記録を再開できる。
- **記録のサーバー同期はない**。機種変更にはバックアップが必要。パスワード再発行・メール送信・サーバー側7日開封判定は未実装。

## 本番設置に必要なもの（未設定）

HTTPSドメイン、Node常駐プロセス、外部へ公開しない永続DBディスクとバックアップ、TLSリバースプロキシ、オーナー最終承認が必要。
ゲートウェイは127.0.0.1だけで待機する。TLS終端からHostを維持して転送し、80番のHTTPはHTTPSへリダイレクトする。別途静的配信でapp/を公開しない。
SQLiteは単一インスタンス用。複数レプリカに同じDBをコピーして運用しない。メールアドレスを含むDBと補助ファイルは公開ディレクトリやGitに置かない。

設定例（実ドメインと非公開ディスクに置換）：

```sh
export MICHIRU_ORIGIN=https://your-approved-domain.example
export MICHIRU_DB=/private/persistent-volume/michiru.sqlite
node runtime/manage.js invite student@example.com
node runtime/gateway.js
```

inviteコマンドが出す招待コードは秘密として本人に別途渡す。この開発作業では実受講生のコード発行・連絡はしていない。
招待・セッションを失効させるには `node runtime/manage.js revoke student@example.com`。登録済みアカウントも停止する。
再ログインは元のパスワードが必要で、再招待による上書き登録はできない。パスワード紛失時の本人確認・再設定は運用前の残課題。

開発テストに限り `createGateway({ development: true, origin: 'http://127.0.0.1:0', ... })` が使える。CLI本番起動ではHTTP・開発モードを受け付けない。

## 11月1日の配布判断

本番HTTPSの動作URL、Safari実機の確認、招待の配布とログイン確認、正式原稿・ミニ解説の承認が未完了。現時点で受講生への配布可とは判断しない。
7日制限は引き続きUI補助で、端末保存の本文を暗号化・サーバー保護するものではない。正式公開までにこの制約を解消・承認する必要がある。
利用者の個人端末での使用を前提とする。共用端末では端末内の記録が残るため、利用後の全削除やブラウザデータ管理が必要。
本番確認では未招待拒否・別アカウント分離・ログアウト・失効・DB再起動後のログイン・バックアップ復元・Safariのダウンロードまで検証する。
